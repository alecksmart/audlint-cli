- (event) Reviewed the current Player Content selector implementation, focused PTY tests, the original Player Content contract, the live rsync progress SPEC, and ADR-0008. This run proposes UX behavior only; it does not change code or synchronization mechanics.
- (assumption) [ASSUMPTION] The primary operator uses a desktop or laptop terminal, prefers keyboard control, and may curate inventories of hundreds or thousands of albums.
- (decision) Preserve the existing fixed-row terminal canvas, incremental row repainting, one visible cursor marker, artist headings, album checkbox rows, NO_COLOR behavior, immediate database persistence, and raw-key session.
- (decision) Preserve synchronization semantics: w remains the explicit direct mirror command after complete preflight; an empty checked set remains valid and can empty the managed player root; selection remains intact on failure; live rsync feedback keeps exclusive ownership of the selector body.
- (decision) Add accelerated navigation without changing sort order: Page Up and Page Down move by one visible page, Home and End reach the first and last album, and Left and Right move to the previous and next artist group. Up and Down remain one-album movement; Esc+letter remains as a compatibility shortcut.
- (decision) Keep Space as the one-album toggle. Add a current-artist bulk toggle whose mixed-state rule is: if every available album under the current artist is checked, uncheck all; otherwise check every available album under that artist.
- (decision) A bulk check must measure every newly checked album first and commit the database changes in one transaction. If any target is unavailable or cannot be measured, change nothing and show a bounded error. Bulk uncheck is also one transaction.
- (decision) Add a non-mutating view cycle for All, Checked, and Unchecked albums. Filtering changes only the visible rows, never the persisted checked set, and retains the current album when it still matches; otherwise it moves to the nearest valid visible album.
- (decision) Use an adaptive compact footer with the common controls and a ? help surface for the full key map. Show visible position and view context rather than only global album position. Controls must remain understandable without color.
- (decision) When no albums are checked, keep a visible safety message that w will empty the player. This is an informational warning, not a confirmation, and it must not weaken or duplicate the existing destructive preflight.
- (decision) Do not add global Select All or Clear All in the first increment. Artist-scoped bulk selection is reversible and bounded; whole-library mutation increases accidental destructive-sync risk and sizing cost.
- (decision) Do not make artist headings selectable or introduce a collapsible tree. Preserve the existing flat album cursor model and use group navigation plus group actions instead.
- (change) The original Player Content contract explicitly lists search, filtering, paging mode, artist-level toggle, and a second selection hierarchy as non-goals. An approved implementation spec for this proposal must explicitly supersede only paging-style navigation, view filtering, and artist-level toggle; search and a second hierarchy remain deferred.
- (assumption) [ASSUMPTION] Text search is deferred because group navigation and checked-state views address the clearest observed friction with less input-mode and Unicode complexity. Search can be reconsidered after usage feedback.
- (decision) Visual identity is unchanged. The proposal inherits Audlint Maintenance terminal colors, typography, spacing, and virtual-window layout; it adds no literal color tokens. Focus, checked state, warnings, and availability remain legible through text symbols and labels when NO_COLOR is set.
- (decision) The full help surface is selector-owned and temporary: ? replaces only the selector body with the key map, and q or ? returns to the list without changing cursor, view filter, or checked state.
- (decision) The body title names the active view and transient outcome. Recommended vocabulary uses Checked for persisted membership and Current for the cursor to avoid overloading selected.
- (assumption) [ASSUMPTION] The first delivery should be one backward-compatible interaction increment: accelerated navigation, artist bulk toggle, checked-state view cycle, adaptive help, and PTY verification. Text search and whole-library bulk actions are not part of this proposal.
- (override) Alec explicitly lifted the original Player Content contract's UX restrictions and asked for a good design. The proposal is no longer limited to backward-compatible flat-list enhancements.
- (decision) Use a hierarchical tree-list as the primary model. Artist rows are focusable group controls with expanded/collapsed state and a tri-state checkbox; album rows remain individually checkable children.
- (decision) Interaction model: Up and Down traverse visible focusable rows; Left collapses an expanded artist or moves from an album to its artist; Right expands a collapsed artist or moves from an artist to its first album; Page Up and Page Down move by one viewport; Home and End reach the first and last visible row.
- (decision) Space toggles the focused target. On an album it toggles one album. On an artist it applies to every available album in the group: mixed or empty becomes all checked, all checked becomes none. Every bulk change is pre-measured as needed and committed atomically.
- (decision) Add / search with a selector-owned Unicode text prompt. Search matches normalized artist, year, and album text, composes with the All/Checked/Unchecked view filter, keeps matching artist context visible, and never changes checked state.
- (decision) Artist group rows show checked count and checked payload, for example [~] Artist (4/9 · 1.2 GB). Album rows retain [ ] and [x]. The tri-state marker is textual so NO_COLOR remains complete.
- (decision) Collapsed and expanded state is session-local and independent from persisted checked membership. Search temporarily derives expansion for matching groups and restores prior expansion when cleared.
- (decision) Do not add a global one-keystroke clear in the default key map. A command/help surface may expose select all visible or clear visible only behind an uppercase or two-step command that states the affected album count; synchronization remains a separate w action.
- (decision) The lifted UX restrictions do not supersede ADR-level safety, path identity, exact track-only snapshot membership, deletion scope, source stability checks, destination postcheck, failure preservation, or temporary-fixture verification.
- (decision) Settle v as the All/Checked/Unchecked view-cycle key.
- (override) Retire the old Esc+letter artist jump in the redesigned interaction model. Slash search becomes the discoverable Unicode navigation path; Escape cancels search editing or clears an applied query and otherwise does nothing.
- (decision) When a search matches an artist name, show all albums under that artist that satisfy the active view. When only album text matches, show the parent plus matching albums.
- (decision) Rename the Maintenance entry and screen title from Player Content Creator to Player Content. Keep code and schema identifiers unchanged unless implementation evidence requires otherwise.
- (override) Use conventional tree-arrow semantics: Left moves an album to its parent or collapses an expanded artist; Right expands an artist or moves to its first child; the keys are no-ops when no deeper or parent movement exists.
- (decision) During slash-search editing, show the terminal caret in one bounded input row. Hide it again on apply or cancel. Reject control input and never execute query text.

- (decision) Alec adopted the accessibility boundary: preserve baseline terminal accessibility—keyboard operation, NO_COLOR, textual state cues, safe bounded Unicode behavior, and terminal-state restoration—but do not build or claim a specialized screen-reader mode.
- (decision) The accessibility boundary does not waive ordinary usability, safety, or portability requirements. Narrow-layout feasibility, Help reachability, Unicode display-cell safety, busy/input ownership, destructive-scope copy, and TTY cleanup remain binding product concerns.
- (decision) Any future screen-reader-specific mode, announcement protocol, or conformance claim requires separate product intent, design, verification, and an explicit decision that supersedes ADR-0009.

ADR-0009 governs the terminal accessibility boundary.
- (decision) ADR-0009 excludes a specialized screen-reader mode, announcement protocol, assistive-technology detection, and conformance claim from this UX. All remaining baseline accessibility, terminal correctness, discoverability, Unicode safety, destructive-scope, input-ownership, and TTY-restoration findings remain binding.
- (override) Keep the mixed artist marker as [-] in both spines; it replaces the earlier [~] example. Artist rows show bounded checked/total count plus checked payload, including sizing and unknown states.
- (decision) Build the visible tree by applying All/Checked/Unchecked to album children, then Unicode query matching, then retaining an artist only when at least one child survives. Projections never change membership. Keep a session-local stable identity and sorted-position focus anchor through empty projections, collapse, search, view, Help, and resize.
- (decision) Search uses separate applied-query and draft buffers. Slash opens the editor with the applied query; Escape discards the draft; Enter applies it and an empty Enter clears search. Matching normalizes candidates and query to NFC then full casefold; Backspace removes one grapheme cluster; malformed/control input changes neither buffer.
- (decision) Terminal rows and the search caret use display-cell width, never byte or code-point count. Prefer Unicode disclosure/quotes/truncation only when the locale and width policy support them; otherwise use unambiguous ASCII fallbacks and safely limit search input to representable text.
- (decision) At supported narrow widths, active view/query and zero-state context live in bounded title/status rows, while the footer falls through exact tiers and preserves a complete minimal '? help | w sync | q' legend. Help is a read-only paged surface with Up/Down, Page Up/Page Down, Home/End, position context, clamped resize behavior, and ?/q dismissal.
- (decision) Album Space blocks checking an unavailable album but permits atomically unchecking a checked-unavailable album without measurement. Artist checking shows bounded 'Measuring artist... n of m', owns input until one atomic outcome, discards queued ordinary input, retains Current, and blocks the whole change if any target is unavailable or unmeasurable.
- (decision) Keep persistent safety context separate from authoritative outcomes. At zero checked, always show that w deletes all content from a bounded safe destination label; errors persist until the next relevant mutating action, success survives a stable repaint, and Help/resize preserve active results. Preflight, transfer, flush, source-stability, and destination-postcheck failures name their stage.
- (decision) w always snapshots the complete persisted checked set, independent of view, query, focus, expansion, or visible rows. Foreground sync owns input from accepted w through rsync, flush, source-stability, destination postcheck, and authoritative redraw; discard ordinary bytes, reset partial key-sequence state, never replay input, and treat resize only as layout.
- (decision) Save original TTY, caret, and scroll-region state once. Restore the prior browser raw/caret state across search, Help, measurement, sync, failure, and resize transitions; restore the original terminal exactly once on q, EOF, error, signal, failed raw-mode re-entry, and unsupported-size exit.
- (decision) Below 12x20, show a bounded too-small state, preserve browser/search/Help/result context, disable Space and new w, and restore/clamp context when size recovers. An in-flight sync remains foreground, continues draining input, and retains its authoritative outcome for display after recovery.
