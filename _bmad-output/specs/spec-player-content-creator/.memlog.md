- (direction) Create one bounded BMAD Lite implementation spec for Player Content Creator; do not split it into roadmap capabilities or speculative work.
- (direction) Access is Main M to Maintenance C; the selector keys are Up and Down to move, Space to toggle, w to synchronize, and q to quit.
- (decision) Unchecked albums are deleted during synchronization because the SD card must mirror the selected snapshot and stay within finite capacity.
- (decision) While the selector is open, the existing right side of the preserved top status bar shows selected album count and total selected payload bytes; every Space toggle updates it immediately.
- (capability) CAP-1: the operator can persist an album selection, see its live total transfer size, and mirror exactly that selection to the configured SD player path from Maintenance mode.
- (constraint) Keep one capability and prefer the existing SQLite owner, Maintenance virtual window, album identity, player path, rsync, and payload conventions.
- (decision) The new player_content_selection table stores only checked rows using the existing natural album identity artist_lc, album_lc, and year_int as its composite primary key; no copied path, display, size, or sync state is stored.
- (decision) Selection initialization and writes belong in lib/sh/sqlite.sh; stale selection identities that no longer join to album_quality are removed when the selector opens because they no longer identify browsable library albums.
- (decision) The selector uses a terminal-height scrolling viewport over albums ordered and visually grouped by normalized artist, then normalized album, year, and id; artist headers are not selectable and Up or Down skips them.
- (decision) Album payload sizes are computed from current source files on selector entry using the existing player-transfer inclusion policy, cached for the session, and added or subtracted immediately after a successful toggle; sync refreshes checked sizes before confirmation.
- (constraint) Toggling and browsing require the database and library but never require the SD card; only w requires the configured player destination to exist and be writable.
- (decision) Synchronization mirrors the selected source-relative album subtrees from the resolved library root to AUDL_MEDIA_PLAYER_PATH with rsync deletion enabled, so every destination item outside the selected payload is removed.
- (constraint) Before any deleting rsync call, resolve and validate source and destination as existing disjoint directories, reject broad or dangerous destination roots, require every selected album source to be readable and contained by the library root, and never create a missing player path.
- (decision) w presents an explicit confirmation naming the destination, selected album count, total bytes, and deletion policy; an empty selection is allowed only through the same confirmation and produces an empty managed player root.
- (constraint) A failed preflight invokes no rsync; a nonzero rsync result is reported without changing the database selection, and the feature does not claim atomic destination updates.
- (constraint) Preserve Bash 5 and macOS and Linux portability; source cleanup is forbidden during selection sizing and synchronization.
- (direction) Focused acceptance tests cover schema persistence and uniqueness, M to C entry, grouped scrolling navigation at about 1600 albums, Space toggles and live top-bar totals, operation without an SD card, mirror deletion, empty selection, path and source safety failures, rsync failure, and payload-size parity.
- (constraint) All verification uses temporary music, SQLite, player, and tool fixtures and never accesses a real library, live database, mounted destination, or destructive media workflow.
- (decision) Capacity enforcement, free-space probing, multiple player profiles, playlists, transcoding, and changes to the existing full-library sync are outside this capability.
- (note) Current code evidence: album_quality identity is unique on artist_lc, album_lc, and year_int; source_path is indexed but not unique; Maintenance already receives the player path and can update the virtual-window right title; existing player transfer uses source-relative layout, rsync deletion inside album destinations, and a defined payload filter.
