- (direction) Use BMAD Lite and decompose only where transition and verification boundaries genuinely differ.
- (direction) Make the Player Content visible inventory authoritative from the live filesystem rather than album_quality.
- (direction) Use SQLite only for checked entries and their cached payload sizes; purge entries dropped from a successfully completed live inventory.
- (decision) Use validated library-relative album paths as Player Content identity and derive display grouping, year, album label, ordering, and sync source from that path.
- (decision) Treat a path rename as the old checked entry disappearing and a new unchecked item appearing; do not guess identity across moves.
- (constraint) Never purge checked state when the library root is missing, unreadable, or only partially inventoried.
- (constraint) Do not parse tree output in production; reuse canonical filesystem and audio-extension helpers.
- (constraint) Preserve _VA grouping, ASCII and Cyrillic jumps, fixed-row rendering, incremental responsiveness, exact payload policy, and all destructive sync safety checks.
- (capability) CAP-1: The selector inventories current readable album directories from the library filesystem and shows only that live inventory with directory-derived grouping and labels.
- (capability) CAP-2: Checked state is keyed by validated library-relative path, cached selected payload bytes appear immediately and refresh incrementally, and dropped entries are purged only after successful inventory.
- (capability) CAP-3: Synchronization builds its checked manifest from the fresh filesystem inventory and path-keyed state without joining album_quality, while preserving exact mirror and preflight behavior.
- (capability) CAP-4: Scanner discovery reconciles an unchanged natural album identity found at a different source path instead of skipping it because content timestamps are unchanged.
- (decision) Keep browser and quality catalog behavior database-backed; this transition changes Player Content authority and separately repairs scanner path reconciliation.
- (constraint) Use temporary fixtures for automated verification and never access a real library, live database, or mounted player in tests.
- (note) Read-only investigation found 16 Jarre catalog paths stale after a directory rename and one additional stale Anugama row; current tests intentionally preserve unavailable database rows.

- (direction) Do not inspect or model destination contents while browsing; rsync owns destination convergence only when synchronization is requested.
- (direction) Show SD filesystem free space independently of selection state instead of mounted status or inferred destination contents.
- (decision) Retire CAP-4 scanner path reconciliation as adjacent scope; do not reuse its capability ID.
- (capability) CAP-5: The selector reports configured SD filesystem free space when available, independently of selected count and size, without walking destination contents.

- (direction) Inventory uses filesystem directory paths and names only; do not inspect audio presence, tags, codecs, media metadata, or payload contents to decide list membership or labels.
- (direction) Every check operation measures that directory again before inserting it; unchecking removes the row, and checking it later creates a new size snapshot.
- (direction) Selector entry obtains selected count and total exclusively through SQL COUNT and SUM over cached checked rows; do not rescan selected sizes or show refreshing state on entry.
- (direction) Synchronization remeasures checked source directories and updates cached sizes because source files may have changed after selection.
- (decision) Do not migrate the current natural-key selection rows; deliberately replace the legacy Player Content table during this development change and start with an empty path-keyed table.
- (constraint) If the library tree cannot be read completely, preserve every checked database row, show a clear error, and return to Maintenance without rendering or purging a partial inventory.
