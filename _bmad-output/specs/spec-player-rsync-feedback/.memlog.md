- (direction) User reports that m -> c -> w shows only Synchronizing player during long writes and requests visible rsync progress.

- (capability) CAP-1 | intent: The operator can see live aggregate rsync progress while Player Content synchronizes the player. | success: A progress-capable rsync produces bounded live transfer updates before the authoritative final result; a rsync without optional progress support still follows the existing completion and failure contract.
- (constraint) Preserve the one root-level exact track-only mirror and every existing snapshot, rule, deletion, flush, source-stability, destination-postcheck, exit-status, checked-selection, and retry behavior.
- (constraint) Probe optional rsync progress support instead of requiring one version or flavor; preserve Bash 5 and macOS/Linux portability under ADR-0003.
- (constraint) Render only sanitized, terminal-width-bounded aggregate updates in selector-owned space; raw filenames, control data, verbose output, and unbounded buffering must not enter or corrupt the canvas.
- (constraint) Progress setup or unsupported progress flags must fall back to the existing synchronization path and must not make an otherwise valid transfer unavailable.
- (constraint) Automated proof uses temporary libraries, databases, destinations, and tool stubs only under ADR-0004; real operator resources require explicit approval.
- (decision) Adopt ADR-0003, ADR-0004, and ADR-0008 as companions because they govern portability, verification safety, and the existing root rsync mechanism.
- (decision) Non-goals: no filename-level transcript, per-file progress UI, cancellation, background transfer, history, browser-transfer feedback, sync_music feedback, or transfer-policy changes.
- (assumption) Aggregate transfer state in the existing Player Content status area satisfies the request for rsync progress; raw per-file output is not required.
- (decision) Success proof blocks a temporary-fixture rsync after emitting progress to show live visibility, then verifies final success, real nonzero rsync failure with preserved selection, bounded unsafe-record handling, and fallback without optional progress support.
