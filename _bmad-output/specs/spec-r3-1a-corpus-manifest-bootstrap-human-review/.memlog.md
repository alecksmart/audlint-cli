- (direction) Headless express mode selected because the user supplied a bounded remediation goal, preservation boundary, required ownership split, and requested artifact outcome.
- (decision) The child slug is r3-1a-corpus-manifest-bootstrap-human-review and it closes only the safe bootstrap gap before existing R3.1 strict inventory.
- (direction) Preserve the implemented R3.1 through R3.5 contracts; R3.1A adds discovery and review handoff without changing strict inventory, staging, verdict, instrumentation, benchmark, or finalization semantics.
- (capability) CAP-1 Read-only corpus discovery: maintainers can enumerate candidate cases and objective file/media facts beneath an explicit corpus root without analysis or corpus mutation.
- (capability) CAP-2 Review-safe draft: maintainers receive a deterministic schema-compatible draft whose automated and human-owned fields are visibly distinct and whose incomplete human fields cannot pass strict R3.1 validation.
- (capability) CAP-3 Human review handoff: a reviewer can complete identity, classification, expectations, provenance, trust, and synthetic lineage, then pass that same JSON object to existing --inventory without a new conversion format.
- (capability) CAP-4 Immutable-source evidence: fixture verification proves bootstrap writes only the declared repository draft and leaves the complete supplied corpus tree unchanged apart from unavoidable read access-time effects.
- (decision) The stable default draft path is _bmad-output/benchmarks/r3-analyzer-corpus-benchmark-baseline/corpus-manifest-review-draft.json.
- (constraint) Draft publication is atomic and must not replace an existing draft by default, protecting partial human review from accidental regeneration.
- (decision) The draft uses the existing schema-version-1 manifest shape with null placeholders for required human-owned fields; it contains no draft-only keys that could leak into the canonical manifest.
- (decision) Automation may populate schema version, discovery timestamp, safe root-relative album and file paths, mechanically derived category and provisional roles, SHA-256, byte size, and objective probe facts.
- (decision) Automation may suggest deterministic candidate case boundaries and ordering but may not claim those suggestions are reviewed stable identities or coverage classifications.
- (decision) Human review owns corpus_id, corpus_revision, stable entry id, confirmation or correction of album grouping, category and case_class, expected source and target profiles, expected decision, expected fake-upscale value, optional analysis mode, provenance, reviewer identity/date, trust, and synthetic generation recipe where applicable.
- (constraint) Bootstrap never runs audlint-analyze, audlint-value, converters, dataset generation, staging, evaluation, benchmarking, finalization, or any database workflow.
- (constraint) Discovery accepts only an explicitly supplied corpus root, stores only normalized POSIX root-relative paths, does not follow symlinks, and fails safely on path escape or unsupported filesystem entry types.
- (constraint) The approved /Volumes/Music/Tests root is read-only: no output, cache, sidecar, temp file, chmod, rename, retag, timestamp write, or generated media may occur beneath it.
- (decision) A completed review draft becomes existing R3.1 input by replacing every required null, confirming automated suggestions, removing generation_recipe for independently sourced cases or completing it for synthetic cases, and invoking the unchanged --inventory CORPUS_ROOT REVIEWED_DRAFT path.
- (decision) Existing R3.1 remains the authority that re-reads objective facts, rejects remaining placeholders or invalid human truth, and writes canonical corpus-manifest.json.
- (constraint) Generated draft JSON uses deterministic ordering, UTF-8, two-space indentation, sorted object keys, LF endings, and one final newline while preserving stable discovered array order.
- (constraint) Automated tests use repository-owned temporary fixtures and prove path containment, symlink and special-file rejection, objective fact accuracy, placeholder rejection by strict inventory, no analyzer launch, atomic no-overwrite, and complete fixture immutability.
- (decision) A draft-format companion carries the field ownership matrix and review-to-inventory workflow because these details are load-bearing but too large for the five-field kernel.
- (note) Wrapper-only content dropped: prior conversational startup state and implementation-session mechanics do not change the R3.1A product contract.
