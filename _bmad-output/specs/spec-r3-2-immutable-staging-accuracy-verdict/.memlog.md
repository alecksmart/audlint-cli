updated: 2026-08-29T16:29

- (direction) Create standalone child SPEC-r3-2-immutable-staging-accuracy-verdict as the second bounded implementation slice of the existing R3 parent contract.
- (decision) The R3 parent SPEC and companions plus R3.1 are authoritative; review found no conflict, so R3.2 narrows their staging and accuracy requirements without changing either contract.
- (decision) R3.2 consumes schema-version-1 corpus-manifest.json only through the strict R3.1 validation contract and does not add, coerce, infer, or redefine manifest fields or trust.
- (capability) CAP-1 — Validated case selection: resolve requested manifest cases from one explicitly supplied corpus root only after full R3.1 validation; preserve manifest order and reject unresolved, missing, escaping, or inconsistent selections before analyzer execution.
- (capability) CAP-2 — Verified isolated staging: snapshot each complete selected case subtree, create a unique temporary stage outside the corpus root, byte-copy the manifest-declared inputs with required layout, and verify the stage before execution.
- (capability) CAP-3 — Staged analyzer execution: invoke audlint-analyze --json only with the staged case path and temporary outputs, never the external corpus path, while capturing exit status, stdout, and stderr.
- (capability) CAP-4 — Trust-aware verdict: compare actual target profile, decision, fake-upscale value, and optional analysis mode with manifest expectations so matches pass, trusted mismatches fail, weak mismatches warn, and operational or contract failures error.
- (capability) CAP-5 — Source immutability and cleanup: repeat the complete selected-subtree snapshot after every attempted execution, invalidate the run for any added, removed, or changed entry, and always attempt stage cleanup.
- (capability) CAP-6 — Aggregation-ready evidence: emit deterministic machine-readable ordered per-case expected and actual values, trust, status, mismatch or error reasons, analyzer evidence, manifest identity, and source-immutability and cleanup outcomes.
- (constraint) The caller supplies the manifest and corpus root explicitly; manifest album_path and file paths remain POSIX-style root-relative identities and no machine-specific corpus root is stored in evidence.
- (constraint) Each run invokes the R3.1 validator in full before selection or copying; unsupported schema, invalid trust or provenance, missing expected truth, malformed entries, duplicate IDs, and other manifest inconsistencies are errors, not weak fallbacks.
- (constraint) The pre/post source snapshot boundary is the complete selected case directory subtree only, including the case root as dot and every descendant found without following symlinks; unrelated cases are not traversed or hashed.
- (constraint) Snapshots compare lstat file type, byte size, permission bits, nanosecond modification and status-change times, regular-file SHA-256, and symlink target; access time is excluded.
- (constraint) Before copying, every declared input must exist as the required regular-file input, resolve inside the supplied corpus root without traversal or symlink mediation, and match the manifest byte size and SHA-256.
- (constraint) Stages use a portable unique temporary directory outside the corpus root and contain fresh byte copies of declared inputs only, preserving required relative layout; no source or stage symlink is followed, and no symlink or hard-link shortcut is accepted as a staged copy.
- (constraint) Stage verification repeats size and SHA-256 checks against the manifest, rejects missing, extra staged-input identities, unexpected file types, symlinks, hard-link shortcuts, or layout mismatch, and completes before audlint-analyze starts.
- (constraint) Only stage and temporary-output paths may be passed to product commands; staging, evidence capture, source verification, and cleanup are not analyzer execution and R3.2 records no benchmark timing.
- (constraint) Structured analyzer output must contain well-typed album_sr, album_bits, album_decision, album_fake_upscale, and analysis_mode when expected; target profile is normalized to canonical SR_HZ/BITS for exact comparison.
- (constraint) A trusted expected mismatch produces case status fail and a nonzero overall result; a weak mismatch produces explicit warn and does not alone make the overall result nonzero; a match produces pass.
- (constraint) Analyzer nonzero exit, malformed or incomplete JSON, R3.1 validation or selection failure, source or stage checksum mismatch, staging or cleanup failure, or pre/post corpus mutation produces error and a nonzero overall result regardless of trust.
- (constraint) Post-execution source verification runs even when analyzer execution or output parsing fails; evidence is captured before cleanup, cleanup is attempted on every path, and a cleanup failure remains visible as an error.
- (constraint) Machine-readable evidence preserves manifest and execution order, case ID, trust, expected and actual comparison fields, mismatch reasons, status, analyzer exit and diagnostic evidence, manifest SHA-256 and corpus revision, and stage/source safety verdicts while sanitizing corpus paths to root-relative form.
- (constraint) R3.2 does not publish benchmark-results.json or baseline-summary.md and adds no new stable runtime artifact; its machine-readable result is the input later R3 benchmark aggregation will consume.
- (constraint) CLI orchestration remains thin in bin/audlint-analyze-corpus.sh; shared manifest, staging, snapshot, verdict, and evidence logic belongs in lib/py/audlint_analyze_corpus.py or focused shared Python modules.
- (constraint) Verification uses repository-owned temporary fixtures only and never accesses /Volumes/Music/Tests, a real music library, live SQLite, mounted sync destination, backup target, or destructive media workflow.
- (constraint) Focused tests prove stage isolation and byte verification, analyzer stage-only invocation, full-subtree source mutation detection, trusted failure, weak warning, analyzer failure, invalid JSON, manifest or checksum error, and cleanup after both success and failure.
- (constraint) Preserve Bash 5, macOS/Linux portability, canonical profile normalization, and audlint-analyze as the sole recode-decision authority; the runner evaluates output and does not reconstruct analyzer policy.
- (direction) R3.2 excludes R3.1 inventory and schema implementation; metadata, decode, probe, cache, fallback, and timing counters; cold/warm or aggregate benchmark reporting; converter benchmarking; synthetic regeneration or checksum reproduction; analyzer threshold, cache, and performance changes; and R3A/R4/R5/R6.
- (decision) Likely implementation touches bin/audlint-analyze-corpus.sh, lib/py/audlint_analyze_corpus.py and possibly focused shared corpus modules, plus test/test_audlint_analyze_corpus_smoke.py or a focused staging test module.
- (decision) Completion requires the focused temporary-fixture corpus tests to pass and the full local release gate make check to pass, with machine evidence showing every required pass, warn, fail, and error behavior and no fixture-source mutation or leaked stage.
- (note) Wrapper-only content dropped: prompt line continuations and HTML nonbreaking-space entities carried no product requirement.
