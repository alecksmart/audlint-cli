- (capability) CAP-2 Safe synthetic reproduction: every manifest entry with a generation recipe is reproduced through the declared audlint-dataset.sh recipe using verified temporary source staging and a fresh temporary destination outside the corpus and repository.
- (capability) CAP-3 Synthetic lineage and output verdict: trusted source checksum, normalized recipe, tool identity and versions, output identities, checksums, byte sizes, and objective media metadata must all match the manifest or verification fails.
- (capability) CAP-4 Concise final baseline summary: the exact parent-defined baseline-summary.md separates synthetic verification, trusted pass/fail, weak warnings, errors, exclusions, runtime, repeated work, fallback cost, environment, limitations, and evidence references.

- (constraint) R3.5 consumes the stable corpus-manifest.json and benchmark-results.json paths and publishes only baseline-summary.md; it does not rewrite either JSON file or create a fourth stable runtime artifact.
- (decision) R3.2 accuracy evidence and R3.3 work counters are consumed through the unchanged R3.4 sample records, preserving their field names, meanings, statuses, reasons, and ordering.
- (constraint) Full R3.1 manifest validation and full R3.4 result-schema validation run before synthetic execution; missing files, unsupported schemas, malformed evidence, invalid references, or aggregate disagreements stop publication.
- (constraint) The SHA-256 of the exact manifest bytes must equal the benchmark manifest identity, and corpus_id, corpus_revision, case identity, trust, category, class, root-relative path, sample and exclusion references, and deterministic order must agree across artifacts.
- (decision) Synthetic selection is every manifest entry carrying generation_recipe, including trusted and weak entries, in manifest order; equivalent declared recipes may be reproduced once only when every associated output remains independently verified.
- (constraint) Before generation, the declared trusted source identity and checksum must resolve to verified manifest input bytes and the normalized recipe must name audlint-dataset.sh, its exact parameters, relevant environment settings, and declared encoder or tool versions without inference or substitution.
- (decision) Trusted source inputs are byte-copied into a fresh temporary source stage and verified again; audlint-dataset.sh receives only that stage and a fresh temporary output destination, never an approved corpus or repository media path.
- (constraint) Synthetic generation is serial with AUDLINT_DATASET_JOBS=1, uses the declared recipe without repairing or updating it, and rejects recipe or installed-tool identity mismatches before accepting outputs.
- (constraint) Generated regular-file identities for each recipe invocation must match the union of its manifest-declared outputs; missing, extra, partial, symlinked, or otherwise undeclared outputs are generation failures.
- (constraint) Each generated output is checked against the manifest with the shared R3.1 objective-fact rules for SHA-256, byte size, container, codec, sample rate, applicable bit depth, channels, and duration; no analyzer verdict participates in this check.
- (constraint) The approved corpus source boundary is snapshotted before and after source staging, and all temporary source and output trees are cleaned on every exit path; source mutation, unsafe destination resolution, or cleanup failure blocks publication.
- (decision) Synthetic reproduction is evidence about lineage only. It never changes manifest expectations, provenance, or trust, and a weak entry remains weak even when reproduction and analyzer output both pass.
- (decision) The final summary uses distinct sections for baseline identity and environment, synthetic verification, trusted results, weak warnings, execution errors, excluded cases, cold and warm runtime, repeated probe and decode work, fallback costs, known limitations, and an evidence index.
- (constraint) Trusted accuracy is summarized by manifest case identity from analyzer accuracy evidence, weak disagreements remain warnings, execution errors remain separate regardless of trust, and exclusions are never folded into passes or runtime aggregates.
- (decision) Runtime findings present verified R3.4 aggregates and cite sample IDs; repeated-work findings compare structured metadata-probe and decode counts across cold and warm pairs, and fallback findings use existing strategy and fallback groups without inferring work from elapsed time.
- (constraint) When evidence cannot establish a comparative fallback cost or warm-work conclusion, the summary states that it is inconclusive instead of inventing a finding.
- (constraint) The summary reports the benchmark environment and toolchain identity exactly, including repository full commit and recorded dirty state, serial settings, iteration count, and the uncontrolled operating-system page-cache limitation.
- (decision) Final consistency requires the live full HEAD commit at finalization to equal the benchmark repository commit; dirty working-tree content is not reconstructed and is reported as a reproducibility limitation rather than silently treated as clean.
- (constraint) The summary identifies the exact manifest SHA-256, corpus ID and revision, benchmark-results SHA-256, benchmark timestamp, repository commit and dirty marker, and every cited manifest case or sample ID so readers can trace claims to machine evidence without duplicating raw records.
- (constraint) Summary serialization is concise UTF-8 CommonMark with LF endings and one final newline. Empty populations are named explicitly, raw sample arrays and diagnostics are not copied into Markdown, and links point to the two sibling JSON artifacts.
- (constraint) Publication builds a temporary summary candidate and atomically replaces the stable baseline-summary.md only after every upstream, synthetic, identity, safety, and cleanup check passes; any failure returns nonzero evidence and leaves an existing summary and both JSON artifacts unchanged.
- (constraint) Automated verification uses repository-owned temporary manifests, media fixtures, tool stubs, temporary project roots, and injected identity and clock facts only; it never accesses the approved external corpus or another real library, database, mounted destination, or destructive workflow.
- (decision) Focused tests cover synthetic success and generation failure, source and output checksum mismatch, wrong recipe or tool lineage, output checksum and metadata mismatch, extra or missing outputs, temp-only destination, weak trust preservation, cleanup, summary sections and evidence links, deterministic rendering, atomic no-overwrite failure, and cross-artifact identity consistency.
