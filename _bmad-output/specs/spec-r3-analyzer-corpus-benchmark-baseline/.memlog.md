- (direction) Headless express mode selected because the user supplied a bounded R3 scope and the immutable staging requirement in a non-interactive tool context.
- (decision) The spec slug is r3-analyzer-corpus-benchmark-baseline, derived from roadmap item R3 and the requested inventory plus accuracy/runtime baseline.
- (direction) Only R3 is in scope: analyzer corpus inventory, trust-aware accuracy verdicts, immutable staging, and serial runtime baselines.
- (direction) /Volumes/Music/Tests is immutable input; this specification run does not access it, and implementation may read it only to inventory or copy declared inputs into temporary staging.
- (decision) The parent product-roadmap SPEC and current architecture overview are adopted companions because their global safety, analyzer-authority, portability, and evidence constraints remain binding.
- (decision) Detailed manifest rules, benchmark protocol, and current brownfield facts live in separate spec-authored companions to keep the kernel lean.
- (decision) The force behind R3 is the absence of a durable representative manifest and current benchmark record, which prevents trustworthy analyzer tuning, cache work, or parallelism decisions.
- (capability) CAP-1 Corpus inventory: maintainers can create a versioned manifest of the approved corpus with stable relative identity, checksums, media metadata, expected source and target outcomes, provenance, and trusted or weak status.
- (capability) CAP-2 Immutable staged execution: maintainers can run corpus evaluation without any command receiving the approved corpus as its working or writable album path, and the run detects any source-tree change.
- (capability) CAP-3 Trust-aware accuracy verdict: trusted mismatches or execution errors fail the run, weak mismatches remain warnings, and results preserve expected versus actual evidence without promoting prior Audlint output to truth.
- (capability) CAP-4 Reproducible runtime baseline: maintainers can record cold-cache and warm-cache serial measurements for audlint-analyze and audlint-value plus safe converter dry-run timings, with per-run work counters, strategies, fallbacks, confidence, and failures.
- (capability) CAP-5 Reproducible synthetic lineage: maintainers can reproduce declared trusted and fake derivatives with audlint-dataset.sh in temporary output and verify their lineage, metadata, and checksums without committing audio.
- (decision) Manifest paths are POSIX-style paths relative to a runtime-supplied corpus root; absolute paths and parent traversal are invalid in committed artifacts.
- (decision) Manifest version 1 separates observed source profile from expected analyzer target profile so the existing ambiguous expected_profile field does not conflate input facts and verdicts.
- (decision) A trusted label requires independently established source or synthetic lineage plus recorded human review; absent, database-derived, or analyzer-derived provenance defaults to weak.
- (decision) Corpus coverage must include genuine 44.1 and 48 kHz families, fake 48/96/192 kHz cases across MP3/AAC/Opus bitrates, sparse genuine high-resolution content, DSD-family sources, large CUE/WavPack inputs, and misleading spectrogram cases.
- (decision) Every command run uses a unique temporary stage containing byte-for-byte copies of manifest-declared inputs; symlink and hard-link staging are disallowed because mutations could escape the stage.
- (decision) Staging and checksum verification occur outside the timed interval so corpus media-copy cost does not contaminate analyzer runtime.
- (decision) A cold measurement uses a fresh stage with no generated Audlint, DR14, converter, or report artifacts; a warm measurement immediately repeats the identical command in the same stage with first-run artifacts retained.
- (decision) Each tool receives an independent fresh stage for its cold/warm pair so earlier tools cannot prewarm later measurements.
- (decision) Converter timing runs only for a read-only or dry-run invocation whose pre/post staged-tree snapshot proves no mutation; unsupported cases are reported as excluded with a reason rather than executed unsafely.
- (decision) Benchmark results record the manifest hash, repository commit and dirty state, command/configuration, host and toolchain facts, run count, per-case elapsed time, outcome, cache mode, track count, metadata-probe count, decode-operation count, strategy, fallbacks, confidence, and failure reason.
- (decision) Accuracy results remain machine-readable and deterministic in manifest order, with separate trusted and weak summaries and explicit expected-versus-actual fields.
- (decision) Committed R3 artifacts contain only manifests, checksums, provenance, generation recipes, logs or summaries safe for source control, and benchmark results; copyrighted or oversized audio stays outside Git.
- (constraint) audlint-analyze remains the sole recode-decision authority; the corpus runner evaluates its structured result and may not reconstruct decision policy.
- (constraint) R3 execution is serial and deterministic; no analyzer or converter parallelism is introduced or benchmarked as the baseline.
- (constraint) No real music library, live SQLite database, mounted sync destination, backup target, or destructive conversion flow may be used.
- (constraint) The approved external corpus must never receive caches, DR reports, manifests, logs, conversion outputs, timestamps, permission changes, or any other write.
- (constraint) Bash 5 and macOS/Linux portability remain mandatory, including portable temporary-directory creation and stable relative-path handling.
- (constraint) Shared instrumentation belongs in lib/sh or lib/py and bin scripts remain thin orchestration layers.
- (constraint) The baseline must expose current behavior, including repeated work and expensive fallbacks, without changing thresholds, decision rules, cache semantics, or worker models to improve the numbers.
- (decision) Non-goals are analyzer threshold tuning, cache-policy optimization, contract convergence, parallel execution, converter implementation changes beyond safe observability, CI/release automation, and corpus audio redistribution.
- (note) Brownfield fact: audlint-analyze-corpus currently accepts list or entries-object manifests, defaults unknown trust to weak, fails trusted mismatches, warns on weak mismatches, and compares target profile, decision, fake-upscale, and optional analysis mode.
- (note) Brownfield fact: audlint-analyze --json still writes .sox_album_profile and may update .sox_album_done, so direct corpus execution violates the immutable-input requirement.
- (note) Brownfield fact: analyzer JSON already exposes tracks, per-track decode_operations, selected strategies, fast-to-exact fallback, segment-to-full fallback, decision confidence, and failure context, but it lacks explicit metadata-probe counters and runner timing aggregation.
- (note) Brownfield fact: audlint-value invokes audlint-analyze and dr14meter and can consume or create album-local evidence, so it also requires an isolated copied stage.
- (note) Wrapper-only content: roadmap state, priority, Next BMAD artifact label, and narrative transitions are not duplicated; all load-bearing R3 outcomes, coverage, tools, metrics, constraints, and exit conditions are preserved.
- (decision) No unresolved product question blocks this baseline: numeric performance thresholds are deliberately outside R3 because this work establishes the measurements future bounded specs will use.
- (decision) Cold and warm refer to application-visible generated evidence, not privileged operating-system page-cache state; the report records that limitation and never claims a hardware-purged cache.
- (decision) Metadata-probe count is the number of external metadata-probe process invocations such as ffprobe or soxi; decode-operation count is analyzer-emitted decode work including separately reported segment-probe decodes.
- (decision) Every applicable benchmark case must have at least one completed cold/warm pair; if multiple iterations are requested, all raw results and the aggregation method are retained.
- (decision) The full product-roadmap SPEC is not an adopted companion because that would pull unrelated capabilities into the bounded contract; all R3-relevant global constraints are absorbed here, while the architecture overview remains adopted brownfield context.
