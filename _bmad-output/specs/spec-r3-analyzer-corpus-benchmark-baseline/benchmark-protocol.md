# Accuracy and Runtime Benchmark Protocol

## Contract documents and generated artifacts

`SPEC.md`, `corpus-manifest.md`, `benchmark-protocol.md`, and `brownfield.md` are Markdown contract documents. They define R3 and are not generated benchmark evidence.

Runtime generation writes exactly these repository-relative artifacts:

| Artifact | Stable path | Format |
| --- | --- | --- |
| Runtime corpus manifest | `_bmad-output/benchmarks/r3-analyzer-corpus-benchmark-baseline/corpus-manifest.json` | One UTF-8 JSON object using the manifest schema. |
| Machine-readable benchmark results | `_bmad-output/benchmarks/r3-analyzer-corpus-benchmark-baseline/benchmark-results.json` | One UTF-8 JSON object containing identity, environment, ordered raw samples, per-case verdicts and counters, exclusions, and deterministic aggregates. |
| Human-readable baseline summary | `_bmad-output/benchmarks/r3-analyzer-corpus-benchmark-baseline/baseline-summary.md` | UTF-8 CommonMark with identity/environment, immutability verdict, trusted and weak accuracy summaries, cold/warm runtime tables, work/fallback findings, exclusions, and failures. |

Both JSON files use two-space indentation, lexicographically sorted object keys, LF line endings, and one final newline; arrays retain manifest and execution order. The Markdown file uses LF line endings and one final newline. Generation may use temporary files, but it publishes only these stable final names and does not overwrite the specification companions.

## Immutable staging protocol

For each tool and corpus case:

1. Resolve the selected case directory as the supplied corpus root plus the manifest entry's `album_path`. Reject missing paths, traversal, and escapes; the resolved case directory is the source immutability boundary for this case run.
2. Before copying or invoking a product command, walk the complete selected case directory subtree without following symlinks. Record the case root as `.` and every descendant by normalized relative path using `lstat`: file type, byte size, permission bits, nanosecond modification time, and nanosecond status-change time. Record SHA-256 content for every regular file and the link target for every symlink.
3. Create a unique temporary stage outside the source root with a portable `mktemp` pattern.
4. Byte-copy all declared inputs while preserving the relative layout needed by album, CUE, and converter workflows. Do not use symlinks or hard links.
5. Verify staged checksums against the manifest before invoking a product command.
6. Pass only stage and temporary-output paths to product commands. Staging, hashing, and cleanup remain outside measured time.
7. Capture structured output, exit status, stderr, counters, and monotonic elapsed time; sanitize committed results to root-relative paths.
8. After command and evidence capture, repeat the complete selected-subtree snapshot and compare it field-for-field with the pre-run snapshot. Any added or removed path, type change, size change, permission change, timestamp change, regular-file checksum change, or symlink-target change is a safety failure and invalidates the baseline. Access time is excluded because read-only traversal and hashing may advance it.
9. Copy only source-control-safe result evidence into BMAD output, then remove the stage.

The snapshot and hashing boundary is only the selected case directory subtree. A case run does not traverse or hash unrelated corpus cases; tests use a complete temporary case subtree as the same boundary. No result is publishable when staging verification or the source immutability check fails.

## Cold and warm semantics

- **Cold:** a fresh stage containing declared inputs and no generated Audlint cache, done marker, DR report, converter cache, report, or output.
- **Warm:** an immediate identical second invocation in the same stage, retaining artifacts generated by the cold invocation.
- **Isolation:** each tool receives a separate fresh stage for its cold/warm pair; earlier tools cannot warm later measurements.
- **Operating-system cache:** page-cache state is uncontrolled and declared in the report. R3 does not require privileged cache eviction or call the result a hardware-cold benchmark.
- **Iterations:** every applicable case has at least one complete cold/warm pair. When more iterations are requested, each begins from a new stage; raw samples and the aggregation method are retained.
- **Serial baseline:** only one measured command runs at a time, with worker settings forced to their supported serial value where applicable.

## Command matrix

| Tool | Cases | Required measurements | Safety gate |
| --- | --- | --- | --- |
| `audlint-analyze` | Every analyzable manifest entry | Cold and warm, structured verdict output | Runs only on the staged album; generated `.sox_album_profile` and `.sox_album_done` stay in stage. |
| `audlint-value` | Entries supported by analyzer and DR14 dependencies | Cold and warm quality output | Runs only on stage; DR reports, proxies, and analyzer caches stay in temporary paths. |
| `cue2flac` | Declared CUE cases | Read-only or dry-run timing | Invocation must guarantee no staged-input mutation and use a separate temporary output root. |
| `any2flac` | Applicable PCM/lossy cases | Read-only, plan-only, or dry-run timing | Pre/post stage snapshot must be identical. |
| `dff2flac` | Declared DFF cases | Dry-run timing | Source and output paths remain separate temporary directories; pre/post source stage is identical. |

If a converter cannot guarantee and demonstrate non-mutation for a case, the runner records `excluded` with a reason and does not execute the unsafe path. A dry-run mutation is a safety failure, not benchmark data.

## Accuracy verdict

The runner compares structured actual target profile, decision, fake-upscale status, and any declared analysis-mode expectation with the manifest.

- `trusted` mismatch: case status `fail`; overall exit nonzero.
- `weak` mismatch: case status `warn`; does not alone make the overall exit nonzero.
- command failure, invalid output, manifest error, staging error, or immutability failure: case status `error`; overall exit nonzero regardless of trust.
- match: case status `pass`.

Summaries keep `trusted` and `weak` populations separate. Each result retains expected values, actual values, mismatch reasons, decision evidence, and the manifest entry ID.

## Work counters

| Metric | Definition |
| --- | --- |
| `elapsed_ms` | Monotonic wall-clock duration around the product command only. |
| `track_count` | Count of analyzed audio tracks in structured output. |
| `metadata_probe_count` | Count of external metadata-probe process invocations, including each `ffprobe` or `soxi` process. |
| `decode_operation_count` | Analyzer-emitted decode work, including separately reported segment-probe decodes when a segment-to-full fallback occurs. |
| `selected_strategy` | Album and per-track analysis strategy reported by the analyzer. |
| `fast_to_exact_fallback` | Whether auto mode escalated from fast to exact. |
| `segment_to_full_fallback` | Whether segment analysis escalated to a full decode. |
| `decision_confidence` | Album and per-track decision confidence, distinct from statistical confidence where available. |
| `cache_state` | Declared cold/warm condition plus observed hit, miss, bypass, or unsupported behavior. |
| `failure_reason` | Stable reason code and human-readable detail for `fail`, `warn`, `error`, or `excluded`. |

Counters come from shared structured instrumentation. The corpus runner aggregates them but does not infer analyzer work from log text or elapsed time.

## Baseline result identity

The machine-readable baseline records:

- Result schema version, UTC timestamp, manifest SHA-256, and corpus revision.
- Repository commit and dirty state.
- Exact command, serial worker settings, analyzer configuration knobs, and iteration count.
- OS/version, architecture, CPU identity and logical-core count, memory, and the page-cache limitation.
- Bash, Python, NumPy, SoX/soxi, FFmpeg/ffprobe, DR14, and invoked Audlint tool versions where discoverable.
- Ordered per-case cold/warm samples, accuracy verdicts, work counters, stdout/stderr evidence references, and exclusions.
- Deterministic summaries by trust, category, case class, tool, cache condition, strategy, and fallback class.

All raw samples remain available. Aggregates never replace the evidence used to compute them.
